# Support

Cardscape is solo-maintained, open-source software. There is no
paid support tier and no SLA. This file explains where to ask
questions, where to file bugs, and where **not** to ask.

---

## Where to ask

| If you want to… | Go to |
|---|---|
| Ask a "how do I…" question | [GitHub Discussions → Q&A](https://github.com/cardscape/cardscape/discussions/categories/q-a) |
| Propose an idea or feature | [GitHub Discussions → Ideas](https://github.com/cardscape/cardscape/discussions/categories/ideas) |
| Show what you built with Cardscape | [GitHub Discussions → Show and tell](https://github.com/cardscape/cardscape/discussions/categories/show-and-tell) |
| Read the maintainer's announcements | [GitHub Discussions → Announcements](https://github.com/cardscape/cardscape/discussions/categories/announcements) |
| Report a **bug** | [GitHub Issues](https://github.com/cardscape/cardscape/issues/new?template=bug_report.md) (use the **Bug report** template) |
| Request a **feature** | [GitHub Issues](https://github.com/cardscape/cardscape/issues/new?template=feature_request.md) (use the **Feature request** template) |
| Report a **security vulnerability** | [SECURITY.md](SECURITY.md) — **do not** file a public issue |
| Discuss a specific PR | the PR's comment thread |
| Discuss a specific issue | the issue's comment thread |

---

## Where NOT to ask

- **Email the maintainer directly** unless the message is
  private (security disclosure, code-of-conduct report, or a
  pre-arranged conversation). Use the public channels above
  for everything else.
- **GitHub Issues** for open-ended questions. Issues are for
  scoped bugs and scoped feature requests. Use Discussions for
  "is this possible", "what's the best way to do X", and other
  open-ended conversations.
- **GitHub Discussions** for security reports. Discussions are
  public. Use the private channel in `SECURITY.md` for any
  security-related message.
- **Pull request comments** for design questions unrelated to
  the PR. The PR thread is for the change at hand. Open a
  Discussion for the broader design question and link it from
  the PR.

---

## Response time

The maintainer works on Cardscape in their available time
(evenings and weekends, mostly). There is no guaranteed
response time. The rough targets are:

| Channel | Target first response |
|---|---|
| Security report | 3 business days |
| Bug report | 7 days |
| Feature request | 14 days |
| Discussion question | 14 days |
| Pull request | 7 days for the first review pass |
| Discussion announcement | n/a — these are the maintainer's own posts |

These are **targets, not promises**. The maintainer is one
person.

---

## When the project outgrows this model

When (if) the community outgrows the solo-maintainer model —
many active contributors, multiple maintainers, a stream of
issues that the maintainer cannot triage alone — the support
channels expand. The plan is:

1. Add **GitHub Discussions moderators** from the contributor
   pool.
2. Add **code owners** for specific directories
   (`.github/CODEOWNERS`).
3. Move Q&A to a dedicated forum (Discourse, GitHub Discussions
   with categories, or a hosted chat) when the Discussion
   volume makes the GitHub UI painful.
4. Adopt a triage rotation among maintainers.

None of this is promised by date. The maintainer announces
each step in the Announcements category when it happens.

---

## Code of Conduct

All support channels are governed by the
[Contributor Covenant v2.1](CODE_OF_CONDUCT.md). Be kind. Be
technical. Disagree on the merits, not on the person.
