# ADR 0012: SQLite-only persistence

- **Status**: Accepted
- **Date**: 2026-08-22
- **Supersedes**: ADR 0001
- **Deciders**: Cardscape maintainers

## Context

The application advertised SQLite, PostgreSQL, and MariaDB at runtime, but only SQLite had migrations, automated tests, CI coverage, and a working deployment path. The shared migration snapshot was generated by SQLite and could not provision the other engines correctly. Keeping unverified provider switches made configuration appear portable while failing during deployment.

## Decision

SQLite is the only supported database provider. Cardscape uses `Microsoft.EntityFrameworkCore.Sqlite`, one canonical migration history, and `ConnectionStrings:Default`. Runtime provider selection and the unused Npgsql/MySQL dependencies are removed.

All persistence access remains expressed through EF Core. SQLite-specific limitations such as `DateTimeOffset` ordering are isolated behind provider-aware repository branches without handwritten SQL.

## Consequences

- Development, CI, Docker, migrations, tests, and documentation describe the same database engine.
- The application artifact is smaller and has no unreachable provider code.
- PostgreSQL or MariaDB may return only through a new ADR, provider-specific migrations, automated integration coverage, and a working deployment target delivered in the same change.
- Existing SQLite databases continue through the canonical EF Core migrations. No compatibility contract is retained for the providers that never had a valid schema.
